# 2026-10-24 问题核查与修复

以提供的 1.txt 为待验证清单，依据源码和本地运行时逐项核查。原清单没有第 8 项。以下修复不修改既有 .env、账号目录、聊天数据库或官方 QQ 二进制，也未重启当前实例。

| 编号 | 核查结论 | 修复结果 |
| --- | --- | --- |
| 1 | 属实。适配器只允许 native 重连，kernel 的退出与断线事件也未请求恢复。仅去掉模式判断仍无法恢复登录。 | 按驱动事件触发退避恢复；内核监测传输状态，网络断线恢复已确认的消息会话，宿主退出后重建并尝试本地快速登录，被踢后重新认证。票据拒绝或无可选账号时等待扫码；主动注销取消重连并等待退出。保留账号固定和不确定发送不重试规则。 |
| 2 | 默认 kernel 与 Linux 镜像确实不兼容。不能通过复制 Windows DLL 让它在 Linux 工作。 | 启动加入 Windows x64 检查；Linux 容器入口明确拒绝 kernel。Compose 要求显式选择实验 native 或模拟用途，数据使用独立卷，健康检查改为 /readyz。没有宣称实现 Linux 官方内核移植。 |
| 3 | 属实。createApp 吞掉驱动启动异常。首次扫码等待则是正常登录阶段。 | 驱动成功加载后才监听 HTTP；启动异常向上传播，清理资源和锁，由 main 以非零状态退出。扫码等待仍开放管理接口，/readyz 返回 503。 |
| 4 | 部分属实。首次私聊缺少 UID 解析；好友和群列表未实现。群号直接作为群会话标识，群发送本身没有这个 UID 前置条件。 | 首次私聊调用官方 UixConvertService.getUid 并缓存映射；接入好友和群列表，处理直接返回与多参数回调。好友接口参数以当前二进制签名为准，兼容两参数和三参数版本。无法解析的目标仍明确失败。 |
| 5 | 属实。单个模型请求会占用唯一 worker。 | AI_CONCURRENCY 默认 4，范围 1–16；不同会话并发，同一会话沿用 SQLite 队列顺序和上下文。离线不调用模型，关闭时取消并等待各工作槽。 |
| 6 | 属实。每条收发消息会同步覆写 validation.json。 | 按状态及里程碑快照去重，异步串行写临时文件再原子替换，关闭时等待写入。100 条消息只新增首次接收里程碑的一次写入。 |
| 7 | 属实。存在实际 .env、数据库和内核账号目录，Git 忽略规则不约束 ZIP。 | 增加 source:export 白名单导出和 SHA256 清单，拒绝符号链接及已有目标目录；增加 npm 文件白名单和更多忽略规则，防止常规源码分发带入本地状态。既有运行数据保留，直接压缩原工作目录仍有泄露风险；分享应只压缩导出目录。没有证据表明密钥已泄露，未擅自轮换密钥或删除账号。 |
| 9 | stopHost 不等待进程退出、丢弃 stderr 均属实。仅凭 kill 不能断定 SQLite WAL 已损坏。登录页 origin 的所谓竞态未复现：Node 的监听回调同步执行，正常请求处理发生在其后。 | 使用 IPC 请求 SDK 正常关闭，等待退出后再完成注销/关闭，超过宽限期才强杀；stderr 限制 256 KiB 并在重连前保留上一份，API 不返回日志正文。登录页改为从已绑定地址计算请求 origin，避免依赖可变初始化状态。 |
