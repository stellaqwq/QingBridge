# Web 管理台

在项目根目录运行 `npm run launch` 或双击 `start.cmd`。启动窗口会打印随机本机端口与访问路径。Web 端只监听 `127.0.0.1`；OneBot 的 HOST/PORT 设置仅作用于机器人接口。

## 源码包首次启动

先运行 `npm ci`。源码包不包含 QQ 官方运行时，宿主清单 `runtime/kernel/adapter.json` 是本机生成文件，不需要手工创建。启动入口会尝试从本机已安装 QQ 自动准备独立运行时；若未找到，请运行 `npm run qq:prepare -- --from "实际 QQ.exe 完整路径"`，或者安装 7-Zip 后运行 `npm run qq:download -- --prepare --activate`，再启动工作台。

已有运行时但缺失宿主、项目被移动或 Node.js 被更换时，启动入口会重新生成对应宿主。配置与账号数据不会被重置。只体验界面可运行 `npm run launch -- --demo`。

## 设置与生效

“全部设置”覆盖 `src/config.mjs` 中全部运行参数，以及 QQ 下载解包使用的 `QQ_7ZIP`。分为 AI 与回复、回复范围、QQ 与运行时、OneBot 与推送、队列与发送、数据与保留、实验驱动七组。顶部和设置内搜索支持中文名称、说明和环境变量名。

图片大小与发送超时位于“QQ 与运行时”，图片缓存保留位于“数据与保留”，Base64 大图需要的请求上限位于“OneBot 与推送”。图片与 AstrBot 表情插件的详细配置见 [图片发送](IMAGES.md)。

1. 设置模型基础地址（如 `http://127.0.0.1:11434/v1`）、模型标识及 API Key。“读取可用模型”调用服务的 `/models`；不支持该接口时可以直接手填模型标识。
2. 在回复范围中设置好友或群白名单，再启用 AI。群聊默认要求 @机器人。
3. 点击“保存设置”。服务会校验完整配置并原子写入 `.env`，提示等待重启。保存失败不会写入部分配置。
4. 点击“重启生效”。安全关闭旧服务后使用新配置启动；页面及访问路径保持可用。新配置无法启动时尝试恢复原服务，已保存的配置仍保留，便于继续修正。

未保存的修改会保留到切换分组之后；“重新加载”可放弃修改。多窗口使用同一份配置时，旧版本的保存会被拒绝，需重新加载后再编辑。启动环境变量覆盖的字段不可在页面修改。

复用其他进程的服务时，工作台可以查看和保存配置，不能替原进程重启，请在原启动窗口停止后重新运行。`npm run start` 配合 `npm run login` 也属于此情况。外部服务重启并修改管理员 Token 后，重新运行 `npm run login` 或 `npm run launch` 生成新的工作台连接。

演示模式 `npm run launch -- --demo` 使用独立临时配置，不写真实 `.env`，不登录 QQ、不发送真实消息，退出后清理。

## 密钥与配置文件

密钥默认不返回到页面。可主动“查看已有密钥”、修改、生成随机值或清空。OneBot 和管理员 Token 必须独立且不少于 24 字符。`SESSION_KEY` 为 64 位十六进制；更换后原加密会话无法读取，需要重新扫码。

“导出配置”生成不含密钥的 JSON。导入只填充非密钥字段，不会立即保存或重启。已有密钥只在明确修改后提交；显式“清空此项”会在保存后删除该值。不要把管理员 Token 提供给 OneBot 插件。

提示词支持多行和混合引号。若值无法直接用 dotenv 引号表示，保存时自动使用 `qqai-base64:v1:` 编码，机器人读取时还原原文；这是文件转义格式，不是加密，页面与配置导出仍显示原文。

## 消息监听

展示实际接收的私聊、群聊消息，以及通过机器人发送并得到确认的消息；即使 AI 未启用或发送者不在白名单，也可以观察接收消息。支持按会话类型、收发方向、正文和 QQ/群号筛选，展开原始事件、暂停显示、清空当前显示和导出 JSON。

页面每 1.5 秒增量读取事件；切到后台时暂停页面轮询，回到页面后补读。记录属于进程内临时历史，最多保存最近 1000 条运行事件，机器人进程退出后清空。大量事件超过容量时，较早的记录会被淘汰。暂停只冻结显示，后台仍接收消息；清空显示不删除 QQ 消息或数据库记录。

消息行按事件 ID 复用；展开的“原始事件”不会因新消息插入而收起，键盘焦点也保留。筛选后再显示同一条消息会恢复展开状态。手机上的会话类型与消息方向有独立标签，保留完整选项宽度。

消息正文使用纯文本展示，不执行 HTML；图片消息段展示为类型及可展开的元数据，Base64 原始图片不会写入监听缓冲区。媒体、群管理等能力范围以 README 中的实机验证表为准。

## 运行日志与任务

运行日志记录连接状态、服务启动、配置保存、AI 排队、生成失败、发送确认、推送错误等事件，支持级别和关键词筛选、暂停、清空显示、导出。日志只允许诊断字段，不记录正文、API Key 或接口凭据。消息内容在独立的消息监听页读取。

任务队列自动展示最近 50 项任务及生成/发送尝试次数。展开“查看消息与回复”可核对会话、输入和回复。“结果未知”表示消息可能已经送达，应先到 QQ 中核对，再标记“已核实发送”或“放弃任务”，不会提供自动重发以免重复发送。

等待任务会按有效期自动转为“失败 / expired”，关闭 AI 或 QQ 离线时仍会处理；正在执行及发送结果未知的任务不会被等待超期流程改写。

“数据与保留 → 保留忽略任务正文”默认关闭。关闭后，新 ignored 任务只保存防重和身份信息；下次启动会脱敏既有 ignored 任务的原始事件、输入和回复正文，无法恢复。开启时按“消息与历史保留”天数保存全文。此开关不控制 OneBot 查询缓存，也不控制 QQ 官方 SDK 或 AstrBot 数据；未回复的消息仍可能保存在这些独立数据层。详见 README“未回复消息如何保存”。

任务详情分别显示处理原因与正文去向：白名单外过滤、正文未记录、正文已脱敏且不可恢复、原消息没有文本，以及旧记录无法确认的内容状态。重新开启保留不会恢复旧正文；字段下方与重启确认框均有明确提示。

真实脱敏会在同一数据库事务中写入 `privacy_audit`，保存时间、改写条数和执行环节，不记录正文、昵称、附件或凭据；同时输出 `ignored_job_content_redacted` 运行日志。“任务队列 → 正文脱敏记录”展示持久记录及累计改写数量，重启后仍可查，幂等检查不会重复产生记录。旧版本未记录的操作不能追溯。新消息只保存防重信息时标为“正文未记录”，不伪造为一次删除操作。

消息页、日志页与任务页说明“内存按条”和“磁盘按天”的范围，并链接到“数据与保留”。页面缓冲由消息与日志共享最多 1000 条，服务进程退出后清空；数据库任务、上下文和 OneBot 查询缓存按当前运行的 `HISTORY_RETENTION_DAYS` 清理。审计表只长期保存上述操作元数据，页面显示最近 10 次，不属于消息正文缓存。

## 验证与源码

“OneBot 与推送”中的“图片访问地址”用于跨主机或容器取图；同机留空自动选择本机地址。QQ 原始图片会先下载，再通过仅授权对应图片的链接提供给 AstrBot。“数据与保留”的图片缓存天数同时控制收发缓存。接收、历史图片回读与访问范围见 [IMAGES.md](IMAGES.md)。

`npm test` 运行全部回归；`npm run check` 检查模块语法；`npm run web:qa` 使用本机 Chrome 的隐藏窗口验证管理台，包含响应式布局和实际交互。可通过 `CHROME_PATH` 指定 Chrome 路径。截图和报告写入 `.impeccable/review/`，全部使用带标记的模拟数据。

`npm run source:export -- <新目录>` 导出源码及 SHA-256 清单，包含 Web 源码、测试、产品与设计文档，不包含真实 `.env`、账号数据、运行时、依赖或截图。首次在新目录运行时，先 `npm ci`、`npm run init`，再按 README 准备官方 QQ 运行时。
